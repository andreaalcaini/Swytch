# Project structure

Swytch switches the input of a DDC/CI monitor (DisplayPort ↔ HDMI) from global hotkeys, a tray
icon or a quick switch window. It is a single Windows executable in Rust with no dependencies: the
Win32 API is called directly (`raw-dylib`), the UI is plain Win32 controls created on demand, and
start at sign-in is a scheduled task so the hotkeys are live a few milliseconds after sign-in.

```text
repo/
├── src/                 the app (Rust 2021, Win32 only), one module per area (below)
├── build.rs             embeds version info (from Cargo.toml) and build/windows/icon.ico via windres
├── build/windows/       icon.ico, generated by `make icon` from src/trayicon.rs (committed)
├── testdata/            fixtures for the unit tests (real monitor replies)
├── docs/                README images
├── scripts/             build-windows.bat (exe into dist/windows/), set-version.ps1 (`make version`)
├── .github/workflows/   ci.yml (checks on push/PR), release.yml (exe + GitHub release on vX.Y.Z tags)
├── .github/scripts/     find-windres.ps1, used by both workflows
├── Cargo.toml           package, version (the only place it is written), release profile
├── rust-toolchain.toml  stable x86_64-pc-windows-gnu + rustfmt + clippy
└── Makefile             dev commands (run `make help`)
```

## Modules (`src/`)

| Module | Responsibility |
| --- | --- |
| `main.rs` | `VERSION`, command line (`dp`, `hdmi`, `toggle`, `install`, `uninstall`, `export-icon`, `icon-preview`), otherwise `app::run` |
| `app.rs` | `App` state (one, on the UI thread, via `app()`), startup order, hidden main window `SwytchMain`, hotkey registration, switch/toggle actions, `CMD_*` commands |
| `tray.rs` | notification icon: add (retried until the taskbar exists), tooltip, warning balloons, right-click menu |
| `trayicon.rs` | the icon drawn with signed distance fields: `HICON` at runtime, `.ico` and BMP preview for dev |
| `ddc.rs` | physical monitors (released on drop), VCP 0x60 get/set, monitor names from the EDID ID, capabilities parsing, "Detect codes" report, `DdcError` |
| `hotkey.rs` | `Hotkey {m, vk}`: labels ("AltGr+F13"), config format, packing for the recorder |
| `config.rs` | `config.ini` parse/serialize with per-key fallbacks, migration from the previous version, atomic save |
| `autostart.rs` | `install` (copy + task + cleanup of the previous version), logon task XML, `schtasks` calls |
| `i18n.rs` | EN/IT strings (`Strings`, `tr()`, `fmt`), language from config or Windows |
| `logging.rs` | `log()` to `Swytch.log` (rotated past 1 MiB), startup timing |
| `paths.rs` | data, install and legacy folders (Known Folders, not env vars), user name |
| `win32.rs` | every Win32 type, function and constant the app uses, string helpers |
| `ui/mod.rs` | lazy UI setup (visual styles activation context, fonts, window classes), control helpers, work areas |
| `ui/quick.rs` | quick switch window (secondary display, always on top) |
| `ui/settings.rs` | settings window; unregisters the hotkeys while open |
| `ui/hotkey_box.rs` | hotkey recorder control (`msHotkey`) |

### Startup (logon task → hotkeys live)

1. Single-instance mutex `Swytch_SingleInstance`, DPI awareness, config, language.
2. Hidden top-level window `SwytchMain` (receives hotkeys, tray callbacks and `TaskbarCreated`).
3. Hotkeys registered (logged with the ms since process creation).
4. Tray icon added; if the taskbar doesn't exist yet, retried every 250 ms and on `TaskbarCreated`.
5. Message loop. Fonts, classes and comctl32 v6 load only when a window is first opened.

### Windows and controls

| Class | What |
| --- | --- |
| `SwytchMain` | hidden main window; `WM_COMMAND` with `CMD_*` runs a menu command (`install` sends `CMD_EXIT` to update) |
| `msQuick` | quick switch window, buttons 201 (PC) / 202 (PS5) |
| `msConfig` | settings window |
| `msHotkey` | hotkey recorder box; value in `GWLP_USERDATA` as `(mods << 16) \| vk`, bit 24 = just recorded |

Hotkey ids 1–4: DisplayPort, HDMI, toggle, quick window (default AltGr+F13…F16, i.e. Ctrl+Alt).

## Data and state

| What | Where |
| --- | --- |
| Preferences | `%APPDATA%\Swytch\config.ini`: `MonitorIndex`, `DpCode`, `HdmiCode`, `AutoStart`, `HotkeysEnabled`, `HotkeyDp`, `HotkeyHdmi`, `HotkeyToggle`, `HotkeyWindow`, `Language` (see `config.rs`) |
| Log | `%APPDATA%\Swytch\Swytch.log` (+ `.log.1`) |
| Visual styles manifest | `%APPDATA%\Swytch\visualstyles.manifest`, rewritten if it differs |
| Installed exe | `%LOCALAPPDATA%\Programs\Swytch\Swytch.exe` |
| Start at sign-in | scheduled task `Swytch` (logon trigger, current user, `LeastPrivilege`) |
| Previous version | `%APPDATA%\monitorSwitch\config.ini` (migrated once), task and `Run` value `monitorSwitch` (removed by `install`) |

## Versions and releases

The version is `version` in `Cargo.toml` (`make version V=x.y.z` also updates `Cargo.lock`). It
reaches the app as `VERSION` (`env!("CARGO_PKG_VERSION")`: tray tooltip, settings title, log) and
the exe's version info through `build.rs`. Pushing a `vX.Y.Z` tag that matches it runs
`release.yml`: checks, release build, `Swytch-X.Y.Z-windows-amd64.exe` + `.sha256` attached to a
new GitHub release with generated notes.
